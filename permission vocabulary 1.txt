ADMIN / ROLES / PERMISSIONS
The Admin controller currently combines several different functions. I recommend separating the permissions conceptually:
admin.access

roles.view
roles.create
roles.edit
roles.delete

permissions.view
permissions.create
permissions.edit
permissions.delete

settings.view
settings.edit
However, we should not automatically create all of these yet because we need to inspect exactly what the Admin methods do before deciding whether role/permission management needs that level of granularity.
REPORTS
reports.view
Current:
Reports::index → reports.view
DASHBOARD
The dashboard is currently not permission-protected.
I would not create dashboard.view yet.
The dashboard normally should be available to authenticated users, while the individual sensitive information displayed on it should be controlled separately.
TECHNICIANS
Current controller:
Technicians::index
Technicians::details
Proposed:
technicians.view
No create/edit/delete methods currently exist in this controller.
PURCHASES
Purchases::index currently has no authorization check.
Proposed:
purchases.view
COSTS
Costs::index currently has no authorization check.
This needs a little more investigation because the actual functionality appears to overlap with the newer project-cost system.
For now:
costs.view
should remain a candidate, not finalized.
